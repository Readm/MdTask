# MdTask 协议规范 (Protocol Specification)

> 版本：0.2（draft）
> 状态：v0.2 实现依据。本文档是 MdTask 生态的"宪法"——所有实现（Obsidian 插件、
> 桌面 app、手机 app）必须遵循本规范，文本文件本身是唯一事实来源。

## 1. 文件格式

- 编码：UTF-8（无 BOM）
- 行尾：LF 或 CRLF 均可解析；序列化时保持文件原有行尾风格
- 文件扩展名：`.md`（惯例，非强制）

## 2. 任务行

任务行是满足以下正则的列表项：

```
^(\s*)([-*+]) \[([ xX])\]\s*(.*?)(\s?▶)?$
```

| 组 | 含义 |
|----|------|
| `\s*` | 缩进（行首空白）。父子关系由缩进长度派生，缩进单元约定为 2 空格 |
| `[-*+` | 列表符号：`-`、`*`、`+` |
| `[ ]` | 未完成；`[x]` / `[X]` 完成 |
| `(.*?)` | 任务文本（不含折叠标记） |
| `\s?▶` | 可选折叠标记：` ▶`（U+0020 U+25B6），仅表示"本任务子树折叠" |

### 2.1 折叠标记（协议扩展点 #1）

- ` ▶` 出现在任务文本末尾 = 该任务的子树处于折叠状态
- 展开状态 = 无标记（文件中只出现折叠态，不引入展开标记）
- 折叠标记**不属于任务文本**：解析时剥离，存入任务的 `collapsed` 字段
- 无子任务的任务行上的 ` ▶` 无实际效果，但保留原样（解析不报错、不重写）
- 编辑原语（§5）必须保留折叠标记

### 2.2 任务文本

任务文本 = checkbox 之后、折叠标记之前的内容，**原样存储**（不 trim 不解析）。
v0.2 不支持任何属性语法；未来属性（日期/优先级）的预留区：任务文本末尾、
折叠标记之前（见 §7）。

## 3. 树结构

任务行按行序排列。设 `depth(line)` = 行首空白长度：

- 任务 `i` 是任务 `j` 的子任务 ⟺ `j` 是 `i` 之前最近的一个 `depth(j) < depth(i)` 的任务
  （markdown 嵌套列表的标准语义）
- 缩进相等或更浅 → 新分支（兄弟或上层）
- 非任务行（普通段落、标题、空行）不参与父子关系计算；解析器按行级规则处理，
  不感知代码块等上下文（代码块的感知由壳层实现负责，见 §6）

### 3.1 折叠的视图语义

`collapsed = true` 的任务，其子树（所有连续的后代任务行）在视图中隐藏。

## 4. 解析模型

```
Document
└── tasks: Task[]        # 按行序
Task {
  lineNumber: number     # 1-based，原始文件行号
  indent: string         # 行首空白原文
  marker: '-' | '*' | '+' 
  completed: boolean
  text: string           # 不含折叠标记
  collapsed: boolean
  raw: string            # 原始行全文（编辑回写时按此还原）
}
```

父子关系由 `depth` 派生，不存储在模型里（视图层需要时构建树）。

## 5. 编辑原语

所有原语都是行级纯函数：输入为**行数组**（由调用方按 `\n` 拆分；`\r\n` 文档
由 `parseDocument` 拆分、`joinLines` 还原），输出修改后的行数组。
**只改动目标行（及定义范围内的行），其他内容字节级不变**（含行尾风格、空行、非任务行）。
单行 API（如 `parseTaskLine`）不接受行尾符；含 `\r` 的行视为非任务行（no-op，不破坏）。
文本级封装（输入完整文档文本）由壳层提供。

| 原语 | 语义 |
|------|------|
| `toggle(line)` | `[ ]` ↔ `[x]`，文本与折叠标记不动。**不联动子任务** |
| `indent(line)` | 缩进 +2 空格（把当前任务变为上一任务的子任务）；顶行不变 |
| `outdent(line)` | 缩进 -2 空格（提升层级，不低于 0） |
| `insert(after, text)` | 在任务 `after` 之后插入新任务行，缩进继承 `after` |
| `move(line, dir)` | 上移/下移**整棵子树**（该行 + 所有连续后代），与相邻任务（子树）交换 |
| `delete(line)` | 删除**整棵子树**；插入新行进行重建 |

- `toggle` 永不改写折叠标记
- `indent`/`outdent`/`move` 移动时折叠标记随行迁移
- 原语对非任务行或不存在行号的行为：返回原文档（no-op）

## 6. 壳层职责边界

| 能力 | core | 壳层（Obsidian 插件等） |
|------|------|------------------------|
| 行级解析/编辑 | ✓ | |
| 代码块内任务感知（跳过代码块内的 `- [ ]`） | | ✓（借助编辑器/渲染器 API） |
| 折叠的视觉隐藏 | | ✓ |
| 键盘绑定 | | ✓ |
| 文件监听/冲突提示 | ✓（变更检测工具） | ✓（接入平台） |

## 7. 扩展预留区

未来属性语法（如日期、优先级）将使用任务文本末尾、折叠标记之前的行内标记。
v0.2 不定义、不解析、不生成任何属性语法。协议演进遵循：
- 新增语法必须是**可选的**（旧文件无需修改即可被新实现读取）
- 新增语法不得破坏 §2 的任务行定义

## 8. 兼容性声明

- 本协议文件是 obsidian-tasks 格式的**子集**：任何本协议文件可被 obsidian-tasks
  正确读取（checkbox 语义一致）；折叠标记 ` ▶` 被 obsidian-tasks 视为普通文本，无害
- obsidian-tasks 的属性语法（emoji 元数据等）不在本协议范围内，本实现不解析也不删除

## 9. 性能目标（v0.2 验收）

- 10MB 文件解析 < 200ms（macOS M 系列参考机）
- 单个编辑原语 < 5ms（对 10MB 文件）
