# MdTask 设计原则：克制与复用优先

> 状态：v0.3 确立（2026-08-17）。本文件是 MdTask 的**指导文档**，所有实现
> 决策必须遵守。违反本原则的代码视为缺陷。

## 原则一：宿主能力优先（不重复造轮子）

MdTask 是"协议 + 多应用"：协议定义**数据契约**，应用是宿主上的薄实现。
宿主的原生能力，一律**直接复用**，不重新实现、不封装、不做替代 UI。

Obsidian 场景的复用清单（对照检查）：

| 能力 | 复用 Obsidian 原生 | MdTask 自己做什么 |
|------|-------------------|-------------------|
| 任务层级（Tab/Shift+Tab 缩进） | ✓ 原生列表缩进 | 无（协议按相对深度解析，不要求固定缩进单位） |
| 勾选 | ✓ 原生 Cmd+L / 点击 checkbox | 额外提供 Ctrl+Enter（宿主无此绑定，用户指定） |
| 折叠/展开 | ✓ 原生折叠箭头 | 仅 hook：原生折叠状态 ↔ 协议 ` ▼` 标记 双向同步 |
| 任务移动/删除 | ✓ 原生移动行/删除行命令 | 无 |
| 任务视图 | ✓ 宿主自带（编辑器即视图） | **不创建独立面板**（v0.2 的树视图面板已移除） |
| 查找/替换/命令面板 | ✓ 原生 | 无 |

## 原则二：协议是唯一新增的东西

MdTask 相对宿主**只新增**：
1. 折叠状态的协议持久化（` ▼` 标记 + 双向同步）
2. 宿主缺失的键盘绑定（Ctrl+Enter）
3. 数据契约本身（解析/编辑原语，core）

任何"新增 UI 面板、新增命令、新增语法"都必须能回答：
"协议需要它吗？宿主真的没有吗？"——两个答案都是否 → 不做。

## 原则三：最小实现面

- 编辑一律走宿主编辑器 API（可撤销、不旁路文件系统）
- 同步逻辑用最简机制（轮询 + hash 守卫），不做事件系统过度设计
- 删除比新增优先：无法回答"为什么要存在"的代码即删

## 原则四：多端一致性的成本边界

各端共享**协议**（文件格式），不共享 UI 代码。Obsidian 端复用原生能力；
桌面/手机端没有对应原生能力时，才允许单独适配（如触屏折叠控件）——
这是"复用"原则在无宿主场景下的合理例外。
