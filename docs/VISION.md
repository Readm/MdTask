# MdTask 愿景文档 (VISION)

> 状态：愿景对齐完成（2026-08-14）。所有决策已敲定。

## 一句话定位

面向会用 markdown 的人的树状任务工具：任务即结构，编辑靠键盘，完成不消失。

## 产品定义：协议 + 多应用

**MdTask 的本质是一个协议**——markdown 树状任务的格式规范（checkbox + 嵌套缩进，
纯文本，无私有语法）。应用是协议的多个实现，任何工具都能读写同一份文件。

- `@md-task/core`：协议的参考实现（平台无关的解析/编辑核心）
- 壳 1（起点）：Obsidian 插件 —— 编辑核心 + 当前文件树视图
- 壳 2（v1.0）：Win/Mac 桌面 app（Tauri）
- 壳 3（v1.0）：手机 app（iOS/Android，完整触屏编辑）

## 核心理念

1. **任务即结构**：树状层级化 Todo（markdown 嵌套列表原生支持），既是 todo list，
   也是任务分解/架构设计工具——同一个文件两种用法。
2. **编辑靠键盘**：Tab 变子任务、Shift+Tab 提升层级、勾选、折叠。编辑要"极快、顺手"。
3. **完成不消失**：勾选后任务保留在列表中，不隐藏。列表永远是完整结构视图。
4. **零学习成本**：会用 markdown 就会用。反模式：功能堆叠、私有语法、查询 DSL。
5. **设计克制、复用优先**（docs/principles.md）：宿主（Obsidian）已有的能力直接复用，
   不重复造轮子、不创建多余面板。MdTask 只新增协议需要而宿主缺失的东西。

## 明确的边界（不做的事）

- 不做查询 DSL / 复杂过滤（v0.2 之前）
- 不做 emoji 元数据语法（日期/优先级留口子，撞到真实痛点再设计极简语法）
- 不内置云同步 / 账号体系（F3 已定外部同步）
- 不做行级冲突合并（团队协作场景，后置）

## 架构推论

- core 重心：树状结构模型（行号/缩进/checkbox/原样文本）+ 行级原地编辑回写
  （只改目标行，其他 markdown 内容原样保留）
- 插件重心：键盘优先的树编辑体验（Tab/Shift+Tab 层级、勾选、折叠、上下移动）
- 兼容性：纯 checkbox 文件天然被 obsidian-tasks 读取（单向兼容免费获得）
